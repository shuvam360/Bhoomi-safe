## 📌 Executive Summary

The North Eastern Region (NER) of India accounts for over **65% of the country's landslide casualties**, driven by intense monsoon rainfall, fragile Himalayan/Indo-Burman geology, and steep slopes. Existing early warning systems rely on coarse regional weather forecasts that fail to capture localized slope dynamics, antecedent soil saturation, and rock lithology.

**BhoomiSafe** is an end-to-end intelligent disaster prevention platform combining:
1. **AI/ML Landslide Risk Engine**: Calibrated on NER geotechnical and precipitation data (XGBoost + Random Forest ensemble with GroupKFold spatial validation and temporal holdout).
2. **Deterministic NDMA Rule-Based Fallback**: Guarantees `/predict` never crashes even if ML artifacts fail to load.
3. **Multi-Source Weather Ingestion**: OpenWeatherMap primary with automatic India Meteorological Department (IMD) / South Asia regional feed failover and calibrated emergency baseline stubs.
4. **Secure FastAPI Backend**: Administrative endpoints secured via `X-API-Key`, citizen reporting protected by `slowapi` rate limiting.
5. **Interactive GIS Command Center**: React + Leaflet real-time risk map and Recharts trend analytics for disaster management officials.
6. **Low-Bandwidth Citizen Reporting Portal**: Accessible on 2G/3G networks for ground-truth crowd reporting.

## 📊 Data Provenance & Real-World Calibration

BhoomiSafe is trained on an expanded **1,328-record dataset** (`data/real_landslide_ner.csv`) covering 10 years (2007–2017) across 49 NER districts. 
- **Real Historical Events (Positive Class, $N=664$)**: Parsed directly from the **NASA Global Landslide Catalog (GLC) / COOLR** filtered to the North Eastern Region bounding box ($\text{Lat } [22.0, 29.5], \text{Lon } [88.0, 97.5]$). For available years (2007, 2008, 2015), 7-day antecedent and 24h/72h rainfall were directly extracted from **IMD 0.25° × 0.25° daily gridded rainfall grids** using nearest-cell lookup.
- **Empirical Climatological Estimation**: For event dates outside downloaded IMD grids and matched non-event days, rainfall features were derived from regional IMD district-month precipitation normals (explicitly labeled `estimated_not_measured` in `data/real_landslide_ner.csv` for full transparency).
- **Matched Negative Sampling (Negative Class, $N=664$)**: Generated by sampling random coordinates across NER from matching monsoon months, strictly enforcing an exclusion zone of **$\ge 10\text{ km}$ distance and $\ge \pm 30\text{ days}$** from any real recorded landslide event.
- **Baseline Preservation**: The original 50-row proof-of-concept mock dataset is preserved in `data/synthetic_baseline/` for architectural comparison.
- **Phase 2 Integration Plan**: Full batch ingestion of the complete historical 1901–2024 IMD 0.25° NetCDF repository and GSI (Geological Survey of India) Bhukosh landslide GIS layers to replace all climatological estimations with measured station/grid records.

## 🏗️ Architecture: Built vs. Planned Status

| Component | Described / Ideal Architecture | Current Codebase Implementation | Status |
| :--- | :--- | :--- | :--- |
| **ML Inference Engine** | Soft-voting XGBoost + RF ensemble predicting probability & NDMA tiers | Loaded via `ml_service.py` (`bhoomi_ensemble.pkl`, release `v2.1.0`), returning probability, risk code, color, and version | ✅ **Built & Operational** |
| **Fail-Safe Fallback** | Deterministic NDMA color tier fallback if ML model is unavailable | `calculate_ndma_fallback()` based on NDMA rainfall + slope thresholds; logs warning and returns valid prediction | ✅ **Built & Operational** |
| **ML Cross-Validation** | Spatial cross-validation without data leakage | `GroupKFold` (grouped by district) + Temporal Holdout (chronological split) documented in `ml/train.py` & `metrics.json` | ✅ **Built & Operational** |
| **Weather Ingestion** | Multi-source dynamic weather feed | Multi-tier failover in `weather_service.py`: OpenWeatherMap -> IMD Keyless API -> Calibrated Baseline Stub | ✅ **Built & Operational** |
| **Weather Integration in /predict** | Prediction automatically pulls live weather if not supplied | Prediction endpoint expects meteorological parameters in body; batch simulator queries district coordinates | ⚠️ **Caller-Supplied** *(Planned: Auto-enrich)* |
| **API Authentication** | Secured administrative operations | Header-based `X-API-Key` auth via `backend/auth.py` protecting alert mutation and report verification | ✅ **Built & Operational** |
| **Abuse Protection** | Anti-spam protection on crowdsourced reports | `slowapi` rate limiting (5 req/min per IP) on `POST /reports` with custom 429 JSON response | ✅ **Built & Operational** |
| **Alert Dispatching** | Automated SMS to State DMAs and Email to NDMA | Multi-channel dispatch in `alert_service.py` (Twilio SMS & SendGrid Email configured via `.env`; operates as mock stub if keys unconfigured) | 🟡 **Stubbed / Config-Gated** |
| **Data Persistence** | PostgreSQL + PostGIS spatial database | In-memory thread-safe dictionaries (`_alerts_store`, `_reports_store`) with pre-seeded demo records | 🟡 **Mock In-Memory** *(Planned: PostgreSQL)* |
| **Static Geotechnical Data** | Dynamic GIS spatial intersection of DEM & Soil | Static CSV lookups in `data/` (`district_metadata.csv`, `dem_metadata.csv`, `soil_types.csv`) | 🟡 **Static File-Based** |
| **Automated Test Suite** | Backend test coverage | 19 automated tests in `tests/` (`pytest` + `TestClient`) integrated into GitHub Actions CI | ✅ **Built & Operational** |
| **Satellite Radar (InSAR)** | ISRO BHUVAN / Sentinel-1 slope deformation | Conceptual architecture in SIH slides | ⏳ **Planned (Phase 2)** |
| **Offline Mesh Network** | LoRa / SMS emergency mesh for zero-connectivity zones | Conceptual architecture in SIH slides | ⏳ **Planned (Phase 2)** |

## 🚀 Quick Start Guide

### Prerequisites
- Python **3.11** or **3.12** (pinned to ensure stable binary wheels for `xgboost`, `scikit-learn`, `numpy`, `pandas`)
- Node.js **18+** and `npm`

### 1. Environment Configuration
Copy the template and configure required environment variables:
```bash
cd bhoomi-safe
cp .env.example .env
```
*(Default development values are pre-filled in `.env.example` so the app runs out of the box without external API keys)*

### 2. Backend Setup
```bash
# Create and activate virtual environment
python -m venv .venv
source .venv/bin/activate  # On Windows: .venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt

# Run the automated test suite
pytest tests/ -v

# Start the FastAPI server
uvicorn backend.main:app --host 127.0.0.1 --port 8000 --reload
```
- API Base URL: `http://127.0.0.1:8000`
- Interactive OpenAPI Docs: `http://127.0.0.1:8000/docs`
- Health Endpoint: `http://127.0.0.1:8000/health`

### 3. Frontend Dashboard Setup
```bash
cd frontend/dashboard
npm install
npm run dev
```
- Dashboard URL: `http://localhost:5173`

### 4. Citizen Mobile Web App
Open `frontend/citizen-app/report.html` directly in any mobile or desktop web browser. It connects seamlessly to the running backend at `http://127.0.0.1:8000/api/v1/reports`.

## 🧪 Testing & Verification

The backend includes a comprehensive test suite executed with `pytest`:
```bash
pytest tests/ -v
```
Tests cover:
- `/health` and `/api/v1/health` returning 200 with model availability metadata.
- `/predict` producing probability bounds $[0.0, 1.0]$, valid NDMA tiers, and model versioning.
- `/predict` returning HTTP 422 for missing required geotechnical fields or inconsistent rainfall logic ($R_{72h} < R_{24h}$).
- `/reports` rejecting out-of-bounds latitude/longitude and non-numeric GPS coordinates with HTTP 422.
- `/reports` accepting valid citizen incident submissions with HTTP 201.

## 🗺️ Future Roadmap

1. **Persistent Spatial Database**: Replace in-memory dictionaries with PostgreSQL + PostGIS and SQLAlchemy ORM.
2. **Auto-Weather Enrichment**: Allow `/predict` to automatically look up coordinates in `weather_service.py` when live rainfall is not provided by the caller.
3. **Computer Vision Verification**: YOLOv8 model pipeline to detect mudslides, rockfalls, and road blockages from user-uploaded photos in `/reports`.
4. **Evacuation Routing**: A* / Dijkstra graph routing on OpenStreetMap road networks to route communities away from high-risk drainage lines.
5. **ISRO BHUVAN Integration**: Ingest optical and SAR satellite imagery for automated slope deformation tracking.
